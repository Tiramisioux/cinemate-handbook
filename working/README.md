# working/

Task-shaped how-to pages — the directory you'll open most often. Pick the page that matches
what you're about to do: [`changing-a-control.md`](changing-a-control.md) for a Redis key,
controller method, or settings key; [`changing-the-gui.md`](changing-the-gui.md) for either
UI surface; [`changing-the-installer.md`](changing-the-installer.md) for install-time
behavior; [`probing-i2c-peripherals.md`](probing-i2c-peripherals.md) for detecting what is
plugged into the I²C bus; [`testing.md`](testing.md) for what to run and what to write;
[`hardware-session.md`](hardware-session.md) for how to settle a claim that needs the real
device. Two trap pages sit alongside them, for the things that fail silently rather than the
things you set out to change: [`browser-side-traps.md`](browser-side-traps.md) for the two
pages that run in someone else's browser, and
[`repository-and-tooling-traps.md`](repository-and-tooling-traps.md) for git, the log, and
the guards.
